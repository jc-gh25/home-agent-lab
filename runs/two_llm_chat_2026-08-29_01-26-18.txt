---

**On the scroll-to-top script:** I'm going to push back — that's not how you do accessibility in 2025. Keyboard users (Tab navigation) won't benefit from a modifier-key trigger (`Meta+K` or `Ctrl+K`) because:
- It requires memorizing an arbitrary shortcut
- Screen readers don't announce custom key-bindings reliably
- Power users have their own tools for this

If you want page-jump functionality, use the native HTML anchor approach instead:

```tsx
// src/components/ui/page-nav.tsx (new component)
"use client"

import { Button } from "@/components/ui/button"
import Link from "next/link"

export function PageNav() {
  return (
    <nav className="fixed bottom-4 right-4 flex gap-2">
      <Link href="#top"><Button variant="ghost" size="sm">↑ Top</Button></Link>
    </nav>
  )
}
```

This works with keyboard navigation, screen readers, and touch targets. It's also what the HTML spec intends for — anchors aren't a bug; they're a feature.
